Scope: AxiAccess Windows adapter, shared legacy response metadata and platform dispatch. This record does not claim an installed sender, signed installer, remote connection or IDE/framework acceptance.

## Evidenced causes and changes

| Plan item | Source cause before repair | Change |
| --- | --- | --- |
| AA-01 | Rust Mac/Linux adapter modules launched `python3`; native Windows and cross-platform records were entangled in `engine.rs` | Keep legacy records/formatters in `engine.rs`; dispatch through native `platform/{windows,linux,macos}.rs`. Linux/Mac adapters are implemented by their own owners. |
| AA-05 | First PID/title/process substring match could choose a different window; per-walk `@eN` was the only node identity; HWND/process birth alone could not detect all same-process HWND reuse | Native Windows reference combines HWND, PID, process creation FILETIME and the window's UIA RuntimeId captured during inventory. Inspection validates that root identity before reading content; unavailable identity is explicit and cannot be treated as a strong reference. Legacy ambiguous selectors return `ambiguousTarget`; tree records add process/window-scoped UIA runtime IDs where available. UIA runtime IDs remain lifetime-scoped, not permanent identifiers. |
| AA-06 | COM initialization failure became successful zero-window inventory; per-query activation was unrelated to permission | `try_list_windows` returns native errors. Compatibility `list_windows` preserves legacy shape but includes the actual issue and `truncated=true`. Windows inventory rejects a noninteractive process window station; screen-reader flag is queried only and is never a permission success signal. |
| AA-07 | Legacy booleans/normalized roles could not distinguish unavailable native control state | Add `native_role` and nullable `states` without removing legacy fields. Windows exposes actual control type and available enabled, focused, off-screen, read-only, selected, toggle, expand/collapse and range state; unsupported or protected value fields remain null. Only getter patterns are used. |
| AA-08 | Limits bounded retained semantic depth/count, allowing long unretained container chains; native calls lacked explicit timeouts | Actual raw depth (64), raw nodes (5,000), retained nodes (250), per-element text and aggregate text limits; cooperative three-second deadline; UIA2 connection/transaction timeouts (500 ms); at most four native reads and one active hierarchy read per application. Output reports truncation/issues. |
| AA-09 | Prior source/plan advertised native events without UIA event registrations; polling consumers could perform repeated full reads | Lazy dedicated MTA owns focus, structure, text/window and selected-property sinks. Callbacks retain no event content and only advance a revision/notify a condition variable. Registration status and failures are reported. After 60 seconds without event consumers, the same MTA unregisters and releases its COM handlers. No full-desktop polling loop is introduced. |
| AA-10 | `CoInitializeEx` errors were ignored; no balancing `CoUninitialize`; `OpenDesktopW` handles leaked and desktop switching was attempted | Each read owns an MTA guard, checks initialization and balances cleanup after COM interfaces drop. Current-session inventory uses native Win32 enumeration; no opened desktop handle or `SetThreadDesktop`. Process and runtime-ID SAFEARRAY handles are released. |
| AA-12 | Name/Value/Text reads occurred without UIA password status filtering | Cache only role/password/state first. Protected or unknown-password-status nodes do not request Name/Value/Text and are leaves with `protected=true`; descendants are not traversed. Routine adapter code does not log captured text. |
| AA-13/14 | Buffer dedup used equal length/preview prefix; manually quoted YAML could misrepresent app strings | Retain separate source buffers, cap text without splitting Unicode scalar values, carry `truncated`/visibility metadata, and serialize labels with JSON escaping in legacy text presentation. |

Relevant files: `src/engine.rs`, `src/platform/mod.rs`, `src/platform/windows.rs`. Shared additive fields were coordinated with the protocol and both native OS adapter owners. Existing nonoptional response fields are retained; new fields use serde defaults for older stored/client responses.

The Windows adapter exports `list_windows() -> Result<WindowListResponse, String>`, `inspect_window(&str, usize, usize) -> Result<InspectResponse, String>`, `inspect_window_with_options(&str, usize, usize, bool)` and `capabilities()`. The last boolean requests full bounded text (`true`) or only bounded previews (`false`); preview buffers retain source identity and are marked truncated for explicit subsequent hydration. Legacy inspection wraps full bounded text. Protocol callers should pass the returned native window identity, not arbitrary titles or bare handles. The legacy `set_screen_reader_flag` symbol remains compatibility-only and reads the existing setting without modifying it.

## OS, content and recovery boundaries

- Windows UIA runs on dedicated MTA threads, not the GUI thread and not the daemon. This adapter does not request UIAccess/elevation or claim access to a secure desktop, logged-out session or another user's desktop.
- Outer timeout does not falsely claim to cancel a blocked COM call. An unfinished read retains its bounded worker/application permit until native execution ends. The sender coordinator's separately owned native worker process can be recycled by the protocol owner; no observed application is restarted.
- Windows inventory uses Win32 metadata without full accessibility scans. UIA2 is required for bounded provider calls. Available metadata is truthful; unavailable process creation identity stays absent rather than fabricated.
- Native runtime IDs are scoped by window/process lifetime. They can change or be reused after that lifetime. An unavailable ID is `None`; shared changes code must not fabricate stable identity from `@eN`.
- Inventory root identity reads stop after their bounded budget; remaining weak references are cleared and reported as partial. A protocol consumer must fail closed on absent identity rather than fall back to a numeric HWND. Runtime IDs are validated, not represented as permanent globally unique window IDs.
- UIA password filtering does not detect every secret in ordinary document text or a provider that wrongly exposes secrets outside protected controls. Ancestor/provider text may have application-specific limitations; no universal secret-removal promise is made.
- Native TextPattern requests are length bounded. ValuePattern's COM API returns one native BSTR before output truncation, so a misbehaving provider's allocation remains a native worker/process isolation concern. `visible_text` is not guessed from a value; unknown visibility stays explicitly unknown.
- Native UIA event subscriptions are implemented, but their coverage is provider-dependent. `nativeEvents` reflects actual registered status, `supportsNativeEvents` identifies implementation availability, and `completeCoverage:false` remains explicit. Unsupported/missed provider events still require bounded explicit reconciliation. Native callbacks invalidate observations; they do not re-read the desktop or declare structural changes by themselves.
- No click, type, key, Invoke, SetFocus, scroll or virtualized-item Realize calls are exposed or invoked. Global accessibility activation is not performed per observation. Provider chats, credentials, signing material and daemon files are untouched.

## Verification performed

Initial local compilation used the default GNU toolchain and failed before Rust adapter checking because `gcc.exe` was not on PATH. A process-only PATH addition for the already installed `C:/msys64/mingw64/bin` resolved that prerequisite without installing tools or modifying global environment.

`cargo check --lib` then reached the combined in-progress source and reported no Windows adapter/type errors after correction of an unsafe-expression grouping and an inferred error-string type. At that point the full library remained incomplete because the concurrent MCP module had not yet been written, the transport needed the Windows filesystem feature, and the observation worker needed a `Read` import. Those are not reported as completed adapter tests or successful whole-product builds.

Subsequent coordinated `cargo check --lib` passed at package version 2.1.0, including the Windows native event sink implementation. `cargo test --lib platform::windows::tests -- --nocapture` passed all three focused tests: ambiguity rejection, stale native identity rejection and Unicode-safe text limits. No failed or skipped tests occurred in that selection (four unrelated tests were filtered out). Live read results will be appended after the binary build. Static compilation and these deterministic tests are not live accessibility acceptance.

Final local verification after root UIA identity, lazy text and native state changes:

- `cargo check --lib` passed with the actual Windows target; a subsequent focused Windows unit selection passed 3/3 with nine unrelated tests filtered out. No expensive provider/model tests were performed.
- `cargo build --bin axiaccess` linked successfully at 2.1.0. The final incremental link after the last metadata/core changes took 14.89 seconds; earlier first-build timing is not a warm-build performance claim.
- An owned, nonactivating WinForms fixture exposed public text and a synthetic password control. Native inventory returned a root UIA identity, inspection observed public text, omitted the synthetic protected text, retained a protected-node indicator, reported native roles/nullable state maps and left protected value state absent. The foreground HWND remained unchanged. Only the exact owned fixture process was stopped afterward.
- A stale native root reference was rejected. One observation traversed nine raw/retained nodes, reported no hierarchy truncation and took 83.3 ms in the final recorded run. This is one small fixture on this machine, not a production latency benchmark or all-app coverage claim.
- Explicit preview-only native inspection returned at most 180 characters per buffer, marked deferred text, retained native source identity and did not falsely mark the hierarchy truncated. The sender's later full hydration is verified separately by the protocol/integration owner.
- The native event thread reported six successful registrations, ready/running true, no registration errors and revision 3. This proves actual registration on this machine, not complete provider notification coverage or every event type's delivery.
- The sanitized receipt is [`docs/evidence/windows-native-20261022.json`](../evidence/windows-native-20261022.json), with exact debug executable/source hashes and toolchain identity. No ordinary desktop titles/text, chat contents or credentials are retained there.

Residual identity boundary: Windows permits UIA runtime ID reuse after native element destruction. Capturing and validating root/runtime identity plus process lifetime repairs the prior HWND-only mismatch; it is not a permanent window ID guarantee. Provider-dependent event coverage remains explicit. A future observed close invalidation should reject affected references rather than taking any UI action.

Official API references used: [MTA threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading), [connection timeout](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_connectiontimeout), [transaction timeout](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_transactiontimeout), [UIA security boundaries](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview).

The [Microsoft UIA event subscription documentation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-eventsforclients) was also read before implementing AA-09. It specifies provider-dependent coverage, one owning add/remove thread, reference-counted callback lifetime and event scope; these informed the MTA registration/unregistration and revision-only callback design.
